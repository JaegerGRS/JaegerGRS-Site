# Cloudflare and security review (October 2026)

Scope: the Worker `jaegergrs-portfolio`, its static assets, the Rig API and the contact form. Method: code reading, the Worker test suite, and read-only requests against production. No test messages were sent, `/api/rig/claim` was not called, and no DNS, firewall, tunnel or deployment settings were changed.

This is a self-review, not an independent audit or penetration test.

| Area | Finding | Status |
|---|---|---|
| HTTPS | HTTP returns 301 to HTTPS; HSTS is sent; `upgrade-insecure-requests` in the CSP. | Verified live |
| Redirects | `www` redirects to the apex; `/about` redirects to `/about/`; unknown paths return 404. | Verified live |
| Headers | CSP (`default-src 'self'`, `frame-ancestors 'none'`), X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy, COOP on pages and API. API CSP is `default-src 'none'`. | Verified live |
| XSS / injection | No inline scripts or styles are allowed by the CSP. Contact fields are validated before being placed in an email. Rig input is whitelisted and range-checked. | Code reviewed |
| Rig authentication | Bearer pairing key, at least 32 characters, compared in constant time. Missing or wrong key returns 401. | Verified live and in tests |
| Pairing key | Generated by `/api/rig/claim` (36 random bytes), only while `RIG_SETUP` is `open` or `rotate`. Stored in Durable Object storage or the `RIG_TOKEN` secret. The production `RIG_SETUP` value is not visible in version bindings; confirm in the dashboard that it is closed. | Needs manual check |
| Replay | HTTPS only. There is no nonce or timestamp, so a captured request could be replayed; impact is limited to one stale snapshot, rate-limited to 1 per second. | Known gap |
| Brute force | Keys are 32+ characters, so guessing is impractical; ingest is rate-limited. Failed attempts are not separately throttled. | Accepted |
| Rate limits | Ingest 1/s. Contact 3 per 10 minutes and 8 per day per salted IP hash. | In code and tests |
| Contact abuse | Origin allowlist, 12 KB cap, honeypot, validation, rate limit. No CAPTCHA/Turnstile. The client timestamp is not validated server-side. | Gaps listed below |
| Secrets | None committed (`.gitignore` covers `.dev.vars`, `.env`, agent config). Production bindings contain plain variables plus the `GUARD_SALT` secret (set 15 October 2026). `scripts/notes-server.mjs` was reviewed: it binds to 127.0.0.1, requires a generated password and writes to the git-ignored `notes/` folder. | Done |
| CORS | Contact: same-origin allowlist. Rig read endpoint: no CORS unless `RIG_EMBED_ORIGINS` is set; GET only. | Tested in suite |
| Cache | API is `no-store`; CSS/JS cached for an hour; static assets cached longer. | Verified |
| Error handling | Unknown API route is 404 JSON, wrong method 405 JSON. Unexpected failures now return a generic 500 (plain, or JSON `server_error` for the API) with no internals, covered by tests. | Fixed in this review |
| Logging | Only an error code is logged on contact failures. Cloudflare observability is on; retention is the account default. | Needs manual check |
| Dependencies | No runtime dependencies and no lockfile, so `npm audit` does not apply. Wrangler runs via `npx`. GitHub Actions are pinned by tag, not commit SHA. | Accepted |
| Infrastructure exposure | `/.env`, `/wrangler.toml`, `/src/`, `/.git/config` and the agent config all return 404. `workers_dev = true` keeps a workers.dev address alive alongside the custom domain. | Decision needed |
| Telemetry | Public output is now an allowlist: CPU name and cores, GPU name and VRAM, RAM size, type and speed, OS name and build, and live load, temperature and RAM percentage. Board model, driver version, storage, uptime, clocks, fan and power are no longer published. | Fixed in this release |

## Issues found during this review

1. **Syntax error in `src/worker.mjs`** introduced by commit `26a5155`: a literal `\n` left `async function handle(` inside a comment, which would have failed CI and any deploy. Repaired and covered by tests.
2. **Public telemetry was wider than the panel needs.** Production exposed the GPU driver version, motherboard model, storage totals and uptime. The allowlist in commit `26a5155` fixes this; it takes effect when this release is deployed.
