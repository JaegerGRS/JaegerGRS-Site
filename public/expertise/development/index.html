Method

How I make decisions.

  1. Start from the constraint. For example, a home PC that must not open inbound ports.
  2. Choose the simplest tool that fits. This site is generated static HTML with a small Worker because that suits a portfolio. I do not claim avoiding frameworks is better in general.
  3. Test where it can fail. Not only where it is easy to test.
  4. Document what is real. Status labels, a changelog and stated limits.

Problem-solving

Examples from the code.

  • A bug found by testing. The Rig API embed was blocked by the browser on other websites. I reproduced it on a second origin and added an opt-in CORS setting with tests. Rig API case study.
  • Stale data presented as live. The live panel separates online, offline and unavailable, and shows last-known specs as such. Live panel.
  • Over-claiming. Project pages mark features as built, partial or planned instead of implying everything works. YouTube AI Story.

Frontend

Responsive and accessible.

Hand-written CSS and JavaScript, checked at 320px and 1280px with automated accessibility testing (axe-core) and no horizontal overflow. This is a target of WCAG 2.2 AA, not a claim of compliance: screen readers, browser zoom and Lighthouse are not yet tested. See the changelog.

APIs

API integration.

Cloudflare Workers with Durable Objects for state, an authenticated update endpoint, a public read endpoint with caching, a rate-limited contact form and a C# client. Details are in the Rig API case study.

Testing

Testing and maintenance.

  • A Worker test script covers authentication, validation, rate limiting, offline behaviour and CORS.
  • A site check enforces unique titles, one h1 per page, image alt text and no broken links.
  • Continuous integration regenerates the pages and fails if the committed output differs.
  • A dated changelog records changes and limits.
  • Not yet covered: browser end-to-end tests and unit tests for the client scripts.

Deployment

Deployment workflow.

Source in Git, pages generated and checked locally, then deployed to Cloudflare with Wrangler. The Grey Signal build page documents the self-hosted alternative.

Security and infrastructure

Privacy, security and safe configuration.

  • Cloudflare deployment: Workers, Durable Objects, static assets and security headers including a strict Content Security Policy.
  • A written security review of the Rig API that lists weaknesses as well as controls.
  • Privacy-focused software is a direction of the Svart Security project, whose pages label what is built and what is planned.

Nothing here has been independently audited.
