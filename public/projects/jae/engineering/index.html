What each workflow does

Confirmed from the repository.

Working

CI validation

On pushes and pull requests to main, one job installs the Python dependencies and runs the pytest suite. A second installs the frontend and builds it.

Working

Hourly health check

Runs every hour on a schedule. It repeats the backend tests and frontend build, and opens one GitHub issue if they fail. Recent hourly runs have passed.

Configured

Tauri MSI build

Runs on a version tag or by hand on Windows. It builds the backend and Tauri app and uploads the MSI as a workflow artifact. It has never run, and it does not create a GitHub release.

Scripts and testing

Repeatable local workflow.

  • PowerShell scripts for install, dev, run, building the backend runtime, building the MSI, cleaning the workspace and a validated push helper.
  • Eight backend test files: API, backups, config, database, hardware detection, model download, model selection and tiers.
  • No interface tests. The frontend is only checked by building it.
A passing workflow shows that the checks ran and passed. It does not prove the app is complete. JAE is still a prototype with no release.

Questions

Engineering questions.

Does JAE need the cloud?

The README says local inference and local data are the default, and that runtime data is not used as a cloud inference backend.

What does it run on?

Windows 10 and 11, with a Tauri shell and a local Python 3.12+ backend managed by Tauri.

How does JAE differ from Personal AI?

They are separate codebases with a shared aim. JAE uses Python, FastAPI and llama.cpp. Personal AI uses Node.js and Ollama.
